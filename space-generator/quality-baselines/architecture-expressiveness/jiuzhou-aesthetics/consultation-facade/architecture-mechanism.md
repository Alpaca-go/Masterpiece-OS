# Architecture Mechanism — ConsultationFacade

> **基准（benchmark）说明**：本文描述旧链路曾经产出的 S 级空间机制，用于 R8.5 评估"新版本是否能复现同等级别的空间结构机制"。  
> **不用于**复制膜天花形状、分格大小、弧线弧度。  
> **来源锚点**：`JZMX-ARCH-03-ConsultationFacade`（anchor registry，imagePath 真实可用，provenance 见 `provenance.json`）。

---

## 1. 核心空间机制（Core Spatial Mechanism）

```
large-scale translucent envelope
  → subtle privacy gradient
    → staff/customer arrangement
      → open plan without hard partitions
```

**一句话表述**：一张大跨度的半透明包络覆盖整片咨询区，私密性靠包络的渐变而非硬隔断自然产生，staff 与客户的空间关系由包络的张力引导。

**机制层数**：4 层（比 reception 少一层，但每层承载更重）。

---

## 2. 评估重点（Evaluation Anchors）

| # | 检查点 | 是否属于"建筑机制" |
|---|---|---|
| A | 半透明边界同时承担功能与美学（不是只好看） | ✔ |
| B | public / semi-private 由空间结构自然产生（不是用屏风/家具硬分） | ✔ |
| C | 建筑机制解决咨询/运营需求（不只是氛围） | ✔ |
| D | staff / customer 关系由包络张力引导（不是无组织） | ✔ |
| E | 大跨度覆盖在视觉上是单一机制（不是多个天花拼贴） | ✔ |

5 项全过 = 5/5。

---

## 3. 对新版本的要求

**允许**：从 V5 字段 derive 一个 4–5 层机制描述。  
**禁止**：把"膜天花 + 大格落地玻璃"固化为 brand 必选；其他品牌（如 YJLF）可能用 paper screen + wood grid 达成等价 4–5 层机制。
