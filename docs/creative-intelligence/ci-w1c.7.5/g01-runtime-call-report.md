### Root cause for the unresolved needRef / evidenceRef SG-01 chain

The model emitted `sourceMap.needs` and `sourceMap.evidence`
as **lists of objects** (e.g.
`{id, type, coverage, statement, factRefs}`) rather than the
contract-required `string[]` of plain IDs. The contract is
defined in `contracts.ts:133` (`CreativeReasoningPromptSourceMap`)
and is enforced by `parseSourceMap` in
`parse-strategic-synthesis.ts:216-245` via the
`isStringArray()` check, which silently falls back to `[]`
when the model output is not a string array.

Consequence in the gate
(`strategic-grounding-gate.ts:130-136`):

```ts
for (const id of artifact.sourceMap.needs) needIdSet.add(id);
// artifact.sourceMap.needs is [] after the parser dropped the
// model-emitted objects. needIdSet is empty.
const knownNeedIds = new Set<string>([...needIdSet, ...artifact.sourceMap.needs]);
// knownNeedIds is a Set of zero strings.
```

Then every `insights[*].needRefs.includes(ref)` check fails
because the string `ref` is never in the empty set. SG-01
fires for every needRef / evidenceRef, even though the IDs the
model emitted are 100% present in the actual truth / need /
evidence carriers.
