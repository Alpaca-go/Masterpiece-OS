# 三个公开场景的产品兼容性阻塞

状态：**未解决，主线合入前须形成并落实单独决策。** 本轮仅完成源码完整性审批和离线回归；没有修改 UI、模板注册或场景映射。`repo:verify` 通过不等于这些选项已可用。

| 公开选项 | 当前事实 | 用户风险 | 后续必须审核的能力边界 |
| --- | --- | --- | --- |
| exhibition | UI/模板有该选项，缺少同名功能程序；另有 display 程序但未批准为兼容映射 | 可选择却在编译时被拒绝；用户可能误以为展陈已受支持 | 展品层级、观看距离、浏览动线、局部可见域；先审查 display 是否真正等价，不能直接取别名 |
| interior_panorama | UI/模板有选项，缺少全景程序与跨区可见权限契约 | 用户可能把全景理解为全店所有区域均可见 | 定义观察点、可见域、跨区隐私与遮挡、全局依赖和实体呈现的差别；不得把局部入口/堂食程序当作全景 |
| counter | UI/模板有选项，缺少独立柜台程序 | 用户请求柜台运营镜头却无法完成 | 工作面、排队、设备、员工/顾客两侧、递交与取用关系；不得默认为 reception、entrance 或 dining |

本轮实测三者仍抛出 `SPACE_TARGET_SCENE_AUTHORITY_UNRESOLVED`，见 `closure-evidence.json`。完整性更新没有放开它们，也没有把未知 subtype 改作 custom。

主线合入前，产品、设计与工程至少共同选择并验收以下一种处理方式：

1. **暂不提供这些公开选项。** 另行授权 UI 能力门禁和清晰的不可用原因，前后端一致。已有保存任务和旧请求不能被静默改成其他场景；保留可读状态及明确的迁移/重新选择步骤，后端继续拒绝未支持请求。发布说明须明确支持范围。
2. **补齐各自能力。** 单独提交场景契约、来源/镜头权威、功能节点与关系、可见范围及隐私规则；只有经审核证明等价时才可新增明确兼容映射。完成中英文、跨项目、显式镜头、未知场景、窗口权限、B1/P7B/公开操作、Golden 和全量离线回归，再分别验收 UI 和生成程序。

上述是后续产品建议，不是本轮授权执行内容。不得只改一个 UI 标签或返回默认场景来掩盖后端缺失；不得以测试全绿、摘要获批或历史图片质量替代能力验收。未落实处理方案前，保持产品兼容性阻塞，不建议将当前选项状态直接合入主线。

这里的“主线/main”沿用任务中的合入阶段表述。本轮没有创建、合并或发布任何主线分支。
