## 目标纠正

四张人工认可作品是离线视觉质量校准基准，不是日常生图依赖。本轮唯一主要回归路线是网页【视觉分析 → 空间生图】的 `standard` 路线，参考数量为 0。保留 `art_direction_reference`，不将其通过等同于标准路线的视觉质量通过。

本轮真实模型调用 0。没有修改原九州项目、历史图片、Golden、冻结 Prompt 记录、提取记录或人工质量状态；没有合并或发布。实现通用的项目级确认机制，九州目标只保存在测试副本及本目录项目输入资料中，没有行业或品牌特判。

## 审计发现与修复

1. 正式标准空间编译本来会调用 `applyUserConfirmedVisualDecision()`，但项目确认记录的写入入口依赖参考图注册，网页没有独立保存和确认入口。
2. 记录没有绑定分析和素材状态；重新分析后无法提示是否仍可用，编译后确认记录变化也没有贯通请求前的检查。
3. 部分审核禁用要求只在 `reviewTask.mustAvoid` 中。普通网页的默认生成任务不填写这些要求时，旧接线未把它们提升到项目级执行约束。本轮将用户确认的这些要求合入有效 Packet 的战略负面约束；没有修改其他项目的通用 Prompt 模板。
4. 标准校验器过去读取模型分析得到的旧气质。本轮从执行快照绑定的用户确认方向读取气质和边界，保持编译、生图请求、校验三者一致。

## 正式数据与网页路径

新增独立所有权模块 `project-design-direction.js`。正式记录位于项目自己的 `project-context/design-direction.json`；历史保存前后快照，包含用户决策来源、确认时间、确认内容 SHA-256、记录 SHA-256、分析及素材指纹。来源明确为 `user_design_decision` 和离线审美校准，不伪装成原始品牌资料，也不声称模型已经学会参考作品。

网页显示【项目设计方向】状态，并提供自然语言字段：空间目标、结构与组织、材料光学、光线、品牌色职责、商业功能、禁用表现及来源。用户保存草稿、核对当前分析并主动勾选确认后，方向才生效。无须编辑 JSON、Codex 注入或上传参考图片。已确认项目在标准空间生图前再次检查状态与摘要，网页和离线业务测试使用同一个标准任务构造函数。

| 状态 | 行为 |
| --- | --- |
| 未设置 | 普通项目继续按原标准路线生成；无图片参考，不自动加入九州决策 |
| 草稿或未保存编辑 | 保留文字，阻断空间生图，提示先确认 |
| 已确认 | 在分析/素材指纹匹配时进入有效 Packet、正式空间编译与 Provider Prompt |
| 需要重新确认 | 保留原内容，禁止静默回退或覆盖；核对新的分析后显式重新确认 |

重新分析请求开始前，已有方向保留并标为需要重新确认；分析失败也不会恢复为虚假的“已确认”。分析/素材/项目资料变化也会即时使确认失效。编译后任何确认记录变化都会阻断旧请求。重新打开项目或创建新的应用服务实例会从项目存储加载相同状态。

历史 `user-confirmed-visual-decision.json` 不被删除或静默覆盖；标准路线可在网页看到历史内容并重新确认到独立记录。原有参考图路线继续使用其自己的确认与资产执行快照。两个入口互不要求先注册图片。未新增公共业务通道，而是在独立工作流已有项目资料读写通道内使用显式用途分派；其他业务不导入、转导出或同步本实现。
