# 跨案例候选规则（3 个案例）

状态：**假设，不是已验证的行业规则。**

以下 7 条只是对 [超级渝](./super-yu.md)、[马记隆](./majilong.md)、[赵得意](./zhao-deyi.md) 三个案例的横向观察。样本量小，且主要基于效果图/品牌视觉；每条置信度只表示“在这 3 个案例中的一致程度”，不表示行业普适性。

使用方式：只能作为设计方向阶段的**建议**，必须人工确认；不自动进入分析或生图。

| # | 候选规则 | 置信度 | 关键边界 |
|---|---|---|---|
| 1 | 门头并置“品牌名 + 品类名”，让路人先看懂卖什么 | 高 | 强势目的地品牌、品类名过长或商场统一门头时不适用 |
| 2 | 把产品证据放到街面第一界面：能开窗做明档，不能开窗用堆头/大图/菜单屏 | 中 | 排烟、补风、城管、商场不允许时不适用；案例 1 是“堆头替代明档”的边界样本 |
| 3 | 用一个“记忆色”贯穿门头、室内、物料；不占最大面积，但成为识别锚点 | 高 | 清淡/高端品类、竞品同色密集、商场色彩规范时需要降饱和或缩面积 |
| 4 | 让超大墙面字/顶招/吊旗承担传播，减少软装和装饰画投入 | 高 | 层高/面宽不足、结构消防不允许、字体不可授权时不适用 |
| 5 | 轻家具、小桌、紧凑排布换效率 | 中 | 正餐宴请、高客单、久坐、无障碍要求高时不适用 |
| 6 | 用齐桌高矮隔断/半墙分区，比整墙通透，但不能切碎主动线 | 中 | 需要私密/隔音、层高不足、主动线窄时不适用；案例 1 完全开放也成立 |
| 7 | 门头副信息放一个“可感知的卖点”（好米、续面、干净好料） | 中 | 承诺无法兑现、权益同质化、广告审批不允许时不适用；品质承诺不等于免费权益 |

## 每条的证据与反例

### 规则 1｜门头并置“品牌名 + 品类名”

- 证据：超级渝门头（`1040g00830vgsvthtlq605p8k0buosrcettjn3j8...jpg`）、马记隆门头（`01hbzs4aefr61p07idq7jc3039.jpg`）、赵得意门头（`0148eyayt8drriu2vae09k3233.jpg`）。
- 反例/边界：目的地型强势品牌、品类名过长或有歧义、商场统一门头限制、外立面审批不允许。
- 置信度：高（3/3 直接可见，品类名显眼程度不低于品牌名）。

### 规则 2｜把产品证据放到街面第一界面

- 证据：马记隆左跨街面窗 + 炭火烧烤灯箱；赵得意左侧明档 + 数字菜单屏；超级渝用米袋堆头 + “米好多”横牌做产品证据（不是明档）。
- 反例/边界：排烟、补风、噪音、卫生、城管、商场不允许明档；进深不足会把油烟带入座区。
- 置信度：中（3/3 都有第一界面产品证据，但只有 2/3 是真正的操作明档；缺排烟、卫生、运营数据）。

### 规则 3｜用一个“记忆色”贯穿门头、室内、物料

- 证据：超级渝橙色（门头侧板/背光、围裙、打包袋）；马记隆铜青绿（门头、绿砖带、餐具、包装）；赵得意红色（门头、卡座、吊旗、票券）。
- 反例/边界：品类气质偏清淡/高端、竞品同色密集、商场有色彩规范；主色面积过大可能显廉价。
- 置信度：高（3/3 都能看到跨门头—室内—物料的重复；色值不能直接作为施工依据）。

### 规则 4｜让超大墙面字/顶招承担传播

- 证据：超级渝整墙黑字书法；马记隆暗红墙 + 白字、入口整排发光顶招；赵得意灰砖墙金字“坊间老手艺”、红吊旗。
- 反例/边界：层高/面宽不足、结构/消防不允许、文案过多或字体不可授权；不能复制他人文案和字体。
- 置信度：高（3/3 都有，且位于顾客主视线）。

### 规则 5｜轻家具、小桌、紧凑排布换效率

- 证据：超级渝浅木方桌 + 木凳/长凳；马记隆浅木桌 + 米色坐垫卡座；赵得意浅木桌 + 灰布椅 + 红卡座。
- 反例/边界：正餐宴请、高客单、停留时间长、无障碍要求高；轻家具的舒适度和耐用度要另算。
- 置信度：中（3/3 家具偏轻、桌型偏小，但没有翻台率、客单价、舒适度数据）。

### 规则 6｜用齐桌高矮隔断/半墙分区

- 证据：马记隆木框磨砂玻璃矮隔断；赵得意绿砖矮墙 + 花格砖；超级渝完全开放（反例，同样成立）。
- 反例/边界：需要私密/隔音的包间、层高不足、主动线窄、消防疏散有要求。
- 置信度：中（2/3 使用矮隔断，案例 1 开放布局同样成立；高度、消防、清洁维护未验证）。

### 规则 7｜门头副信息放一个“可感知的卖点”

- 证据：马记隆三块权益牌 + “免费畅饮”；超级渝“米好多 吃两碗饭” + 米袋堆头；赵得意门头“干净用好料”。
- 反例/边界：承诺无法兑现（续面/畅饮成本）、权益同质化、广告/商场审批不允许；品质承诺不是免费权益。
- 置信度：中（3/3 都有副信息，但类型不同：权益 / 产品暗示 / 品质承诺；兑现能力未知）。

## 来自冯烫烫的单案例假设（不算规则）

以下三条来自 [冯烫烫](ftt-feng-tang-tang.md) 的分析/覆盖/验收记录，目前**只有 1 个案例**，因此放在这里作为“待验证假设”，不并入上面的 7 条规则。

| # | 假设 | 证据 | 验证方式 |
|---|---|---|---|
| warm-low-light | 社区烟火气小馆，暖黄低照度优于明亮均匀；模型默认偏亮，需要人工覆盖 | 分析 packet 明确禁止“昏暗氛围光”；v1 太亮被否；v2 过暗后回调；v8 验收 | 在潮牛帮或下一个社区店做“默认 vs 覆盖”对照 |
| hood-in-structure | 明档排烟罩应收进木构/造型，不能成为独立红黑金属体 | v1 红黑烟罩抢主视觉；v3/v8 木构包住 | 同上，比较两种做法的图 |
| lived-in-detail | 菜单板、价签、食材筐等生活细节提升烟火气；但价格必须真实 | v3/v8 的密度与细节；v8 价格是模型编的 | 记录“有细节/无细节”两版，并核对价格来源 |

### 状态复核（2026-10-29，仅复核既有证据）

仍为假设，不升级规则；自动校验通过不等于人工验收。

| slug | 当前证据 | 边界 | 状态 |
|---|---|---|---|
| warm-low-light | 冯烫烫人工覆盖后验收；潮牛帮单对单图支持暖光与密度组合；蛙耶干净对照未见损害 | 暖光、密度等变量共同改变，无法归因于照度；旗舰感可能稀释，暗部仍须可读 | 支持-带边界 |
| hood-in-structure | 冯烫烫验收图烟罩收进木构；潮牛帮对照与蛙耶观察中也收进结构 | 单图且与其他控制共同变化；可能过度传统化，结构、排烟与消防可落地性未验证 | 支持-带边界 |
| lived-in-detail | 冯烫烫验收图有生活细节；潮牛帮对照细节增加，但出现编造价格与重心偏后厨 | 细节增多尚不等于就餐氛围更好；素材外道具、菜单墙及事实真实性须分别核对，默认禁止数字价格 | 不确定 |

### 对照结果：暖光与烟罩（潮牛帮）（2026-10-28）

- **设置**：同一份分析与同一项目；对照组用中性指令，实验组在中性指令后追加暖光/烟罩经验 + “密度优先 + 品牌色克制”，其余参数完全相同（dining / three_quarter_wide / 16:9 / in_image / 同一 avoid 列表）。
- **结果**：
  - 对照组：更亮、更冷、灰水泥感强，室内几乎无人，明档排烟罩是独立的黑/橙金属体。
  - 实验组：暖木天花与暖光、室内有用餐人群、排烟罩收进木构屋顶，烟火气明显更强。
  - 两张图自动校验均 `passed`，品牌文字正确。
- **判断**：
  - **warm-low-light 成立（本例）**：暖黄偏暗 + 密度确实让“烟火气”更强；对照组偏“干净的商场店”。
  - **hood-in-structure 成立（本例）**：排烟罩收进木构后不再是独立金属体。
  - **新边界**：实验组出现过传统风险——厝角头更像庙宇/日式屋顶，品牌“现代传统主义”的现代感被削弱。下次注入时应同时加“用抽象结构与现代材料压住传统感，不要民俗化”。
- **强度**：单项目、单对单图，未排除随机性；只能记为“1 次对照支持（带边界）”，不能升级为跨案例规则。

### 反例测试：蛙耶（2026-10-28）

- **设置**：商场 IP 品牌（蛙耶，紫/绿/橙、IP 吉祥物、炭锅牛蛙）；同一份分析，对照组用中性指令，实验组追加同一套 暖光、烟罩 + 密度 + 品牌色克制经验；其余参数相同。
- **结果**：
  - 对照组：明亮的商场旗舰感，紫色壳体、霓虹射线、IP 装置，室内较空。
  - 实验组：暖木天花、密度更高、排烟罩收进木构，紫色保留但降为家具/门头点缀，整体从“旗舰店”变成“热闹的商场店”。
  - 实验组**没有**出现红砖/铜锅；模型把经验翻译成了原则，而不是复制元素。
  - 但实验组自作主张加了一辆摩托车和一个头盔蛙（素材里没有），属于“生活感/年轻感”注入带来的**品牌叙事道具幻觉**。
- **判断**：
  - “商场 IP 品牌会被这套经验弄坏”这个预期**没有被清晰证实**；更像“换了一种成立的表达”，旗舰感被稀释但没有崩。
  - 真正的问题是**注入会诱发模型发明品牌道具**（摩托车），这比风格偏移更危险。
  - 两张图自动校验均 `failed`，原因相同：出现“霓虹灯”（品牌本身就有射线语言，与我们的 avoid 冲突）+ 未出现锁定标语“蛙够大 肉才多”。属于测试设置问题，不是两版之间的差异。
- **强度**：反例不成立，但暴露两个新风险（道具幻觉、旗舰感稀释）；需要品牌方给出“旗舰感 vs 热闹感”的取舍标准，否则无法判定哪版更好。

### 第二组反例：蛙耶（干净对照，2026-10-28）

第一次反例把经验写进 `currentInstruction`，两版都因“霓虹灯 + 缺锁定标语”校验失败，且实验组发明了摩托车。第二次改为：

- 把锁定标语“蛙够大 肉才多”写进指令；
- 允许品牌本身的射线语言（从 avoid 移除“霓虹灯”）；
- 经验走新的 `knowledgeContext` 字段，不再混进指令；
- 编译器自动附带 guardrail：只作参考、不复制元素、不发明素材里没有的道具/角色/文字。

**结果**：

- 两版均 `passed`，品牌文字正确；
- 实验组没有变差：保留了紫色主色和 IP 装置，多了室内纵深、菜单板、用餐人群和明档运营细节；
- **没有再出现摩托车或头盔蛙**；经验里的“品牌色只做局部”被模型忽略，紫色仍然是主色——说明模型把经验当建议，而不是硬性风格。

**判断**：干净对照下，知识注入没有损害商场 IP 品牌；guardrail 似乎降低了“道具幻觉”。但这仍是单对单图，且两次 A 测试的指令不同，不能把差异全部归因于 guardrail。

### 第三组：生活细节（潮牛帮，2026-10-28）

- **设置**：同一项目、同一分析；对照组中性指令，实验组通过 `knowledgeContext` 注入 `lived-in-detail`（“桌面菜品、菜单板、价签、食材筐等生活细节提升烟火气；可以略挤；价格必须真实，不要编造”）；其余参数相同。
- **结果**：
  - 对照组：干净的店面，四块菜单屏、明档与蒸汽、室内有顾客。
  - 实验组：增加了带价格的整面菜单、备餐台与多口锅、牛部位图、“取餐口”标识、调料与餐具；细节明显更多，但构图更偏“后厨/备餐”，就餐氛围被推到后景。
  - 两版均 `passed`。
- **判断**：
  - **细节确实变多**，`lived-in-detail` 在本例成立；
  - 但**“价格必须真实”没有生效**：实验组仍然生成了具体价格数字。提示词无法保证价格来源，说明“细节”与“事实真实性”必须分开控制；
  - 副作用：细节注入会把画面重心从“就餐体验”推向“操作现场”，需要配合镜头/构图约束。
- **强度**：单对单图；成立但有“编造价格”和“重心偏移”两个边界。下一步要么禁止数字价格，要么接入真实菜单。

### 新增三个奶茶/点心案例后的补充（2026-10-30，观察）

新增 [乾隆酥院](qianlong-pastry.md)、[吉果鲜点心](jiguo-fresh-pastry.md)、[踢桃](titao-chaoshan-juice.md) 三张卡。除常规证据外，有一件事**与现有策略冲突**，必须记下来：

**价格策略 A（默认图内不出现数字价格）在饮品/档口/连锁业态里是错的。** 踢桃的灯箱菜单明码标价（手打牛油果冰 ¥20 一类），吉果鲜的立面与价目表直接印促销价（如"焕新升级 7.8 折"、多档单品价）。对这些业态，标价是经营必需，也是顾客决策信息；一刀切"不出现数字"会让画面失真，甚至比编价格更不专业。

建议（**未实施，待真实对照**）：把价格轴改成**按业态默认**——档口/连锁/饮品默认"只用真实菜单价"（`real_menu`，前提是用户提供真实菜单），正餐/中高端默认"不出现数字"（`none`）。改默认值属于产品策略变更，需要一次"同一项目、换价格轴"的对照，且要用户确认口径。

其他观察：

- 规则 1（品牌 + 品类并置）：三例都成立；乾隆酥院把品类放在"酥院"里，吉果鲜用"鲜点心"，踢桃用"潮汕果汁冰"副标。
- 规则 4（超大墙面字/顶招）：**吉果鲜是反例**——立面靠红色灯箱带 + 橱窗海报，没有大字墙；街边白盒形态下"立面即招牌"。
- 规则 5（轻家具）：吉果鲜与踢桃几乎没有堂食家具，属于"无座位"极端；乾隆酥院是柜台零售，也没有正餐桌椅。

### 对三条单案例假设的影响（仍为假设）

- **warm-low-light**：新增两个明显反例——嘿小冒菜（快餐冒菜）走“明亮 + 橙白”，吃山（云南菜）走“明亮暖黄”，都不是“暖黄偏暗”；辣三俏（火锅/夜间/重口）才接近昏暖。判断：暖度与照度取决于**时段与品类**（夜间/重口/慢食偏暗，快餐/日间/商场偏亮），不是“社区店通例”。仍需自有项目对照才能改写。
- **hood-in-structure**：良卤的明档是**无现场烹饪的现捞冷柜**，所以根本不需要烟罩；大山牛夫的明档是切配展示。判断：这条假设的前提是“现场有明火/油烟”，无烹饪的档口不适用。边界成立，假设不升级。
- **lived-in-detail**：吃山的“货架 + 玻璃罐 + 秤 + 红菱形菜牌”、大茶饭的“布幔 + 竹编灯笼 + 竹椅”、辣三俏的“老海报 + 搪瓷杯”都属生活化细节，且**没有出现编造价格**；良卤的菜单则出现统一 12.00 的真实感标价。观察：细节来源可以是“物产陈列/旧物”，不一定靠菜单墙——但这条仍是单案例假设 `lived-in-detail` 的延伸，不是新规则。

### 这批案例暴露的新问题（待办）

1. **7 条规则全部只有“正向观察”**：10 个案例里没有一个是“做了但失败”的失败样本，规则仍然缺反例。

## 这些规则还缺什么

1. **实景与运营数据**：三组都是效果图，无法验证落地、翻台、维护成本。
2. **反例项目**：目前没有“做了但失败”的案例，规则缺少失败样本。
3. **跨品类检验**：三条都来自中式快餐/正餐，不能直接推到咖啡、烘焙、高端餐饮。
4. **与冯烫烫的交叉验证**：目前只有一条自有项目，尚未形成 2–3 个项目的验证链。

升级条件：每条规则至少在一个新项目上被显式应用并记录结果，且保留反例，才可从“候选规则”进入下一层。
