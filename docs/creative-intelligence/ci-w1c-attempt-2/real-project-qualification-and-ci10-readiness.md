### 19.1 Root cause of the collapse

The drive script's synthetic brief
(`apps/web-runtime/scripts/ci-w1c/drive-ci-workflow.mjs` lines
260–280) is:

```
# ${projectJson.projectName} — Creative Brief
${projectJson.description || '...'}
## Direction Intent
请基于项目的视觉方案与品牌上下文，输出与品牌气质一致的创作方向。
不引入新事实；所有事实来源于项目 project.json。
```

The only thing that differs between G01 and G02 is the
`projectName` in the title. The `description` field is
**identical** in both project.json files
(`基于已上传的视觉样本完成契合增强分析；品牌与行业信息由素材提炼自动识别；建议与品牌相关事实皆标为待确认。`).
The "Direction Intent" is verbatim. So the model receives
effectively the same input text for both projects and produces
the same Concept / Direction / Canon outputs.

This is a **test-infrastructure finding**, not a production
defect:
- The model is not given any project-specific creative input
  in the brief.
- The project's visual context (visualContextVNext) is loaded
  for the documentContext stage but is not surfaced to the
  direction generation stage.
- The CI Truth layer's locked.facts is correctly empty /
  identical for the synthetic brief, so no conflict surfaces.

The recommendation for a future qualification retry: the brief
generator must surface project-specific creative intent AND
avoid triggering the locked.facts extractor. A constraint-aware
brief wrapper that pulls the project's visualContextVNext summary
and threads it into the brief (without restating project.json
facts) would be the right path. The CI-W1C.3 PART I host
identity diagnostic is not the right place to fix this; the
fix is in the qualification harness (test-infrastructure scope,
allowed per PART X).

The `MASTERPIECE_CI_W1C_BRIEF_PATH` env var added in this
qualification phase (drive script change) is the foundation
for the next retry: the harness can now inject a project-specific
brief. But the **conflict-detection gate** then blocks
project-specific briefs because the AI extracts creative intent
as `locked.facts` and conflicts with project.json. The
qualification did not have a chance to test a
"non-conflicting project-specific brief" because every attempt
triggered at least one source_authority_mismatch on
`locked.facts` / `business.industry`. The next retry must
resolve the brief-extraction policy (either project.json should
include a `excludedFromBriefExtraction` field, or the brief
should be marked as "creative-intent-only" and the document
context extractor should skip locked.facts extraction on it).
