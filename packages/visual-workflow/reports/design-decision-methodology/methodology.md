# 项目设计决策方法论：跨项目实验

状态：离线研究候选，尚未接入生产分析或生成。2026-10-24。

## 目的与边界

把九州美学 P7/P7a/P7b 中人工形成的推导、约束和复核方法，转换为可在其他项目重复执行的工作规程。当前适用范围是空间设计；包装和平面需另行制定媒介规则。不得把空间节点直接推广为全部设计媒介。

本轮只增加说明和离线测试。原生产代码、Prompt、Compiler、Adapter、模型设置、Golden、完整性记录和项目数据保持原样。没有新增自动决策引擎，也没有把人工写好的案例当作模型自主分析成功。

## 七步工作规程

1. **证据分层**：分别列出原始素材事实、业务需求、分析推断、设计提案、用户确认。每条绑定当前项目的素材或字段路径。品牌色排序不能证明空间面积；材料名称不能证明构造；旧项目成功图不能成为新项目的事实。
2. **定义问题与保留项**：说明现状、目标及影响，逐项确定哪些有效关系要保留。禁止把“高级感不足”作为没有观察依据的万能诊断。没有足够证据时提出待确认问题。
3. **建立使用关系**：列出当前镜头节点、使用者、动作、先后顺序、相邻/隔离关系、视线、通行与隐私边界。其他房间可以作为镜头外依赖，不要求全部同框。节点数量由项目需求决定。
4. **分配视觉职责**：核心品牌元素必须写明载体、位置范围、功能、与建筑或产品的关系、视觉主次。允许项目明确选择强色、大型装置或复杂曲面；不得把九州的“局部弱紫、珠光薄片”推广成通用审美。
5. **形成可执行决策**：用“主体 + 动作 + 作用对象 + 范围 + 关系 + 可观察条件”描述。示例：面询台分隔人员双方，两侧各有朝向对方且可进出的座位。两把椅子和一台电脑只是物件数量，不足以证明使用关系成立。
6. **做最小修正与语义检查**：列出保留项、改动项、允许变化项。压缩重复表达，但保留关系、否定边界和独立职责。核对编辑字段、有效 Packet、正式 Prompt 与实际 Provider 请求；发现正负要求冲突时停止，不能以字符匹配通过代替语义判断。
7. **按证据验收**：分别给出表达保真、图像可见关系、无法从图像确认的工程事项。失败后记录具体违反项，再决定下一轮修正。不得自动增加重试或修改 Golden 使其通过。

## 决策卡（提案模板，不是新增持久化 schema）

| 字段 | 内容要求 |
|---|---|
| 项目 / 场景 / 来源版本 | 防止跨项目和过期分析混用 |
| 证据引用 / 来源类别 | 原文、素材位置或当前 Packet 路径；推断需明确标注 |
| 问题 / 目标 / 理由 | 说明为何要改变，不能只有风格形容词 |
| 主体 / 动作 / 载体 / 作用范围 | 缺失范围保持未知，不填猜测比例或尺寸 |
| 功能节点及关系 | 人如何使用，物件如何相互作用 |
| 保留项 / 修改项 / 自由变化项 | 防止修正一个问题时破坏已经有效的设计 |
| 禁止项及依据 | 只约束当前项目中确有依据的风险 |
| 可观察验收条件 | 可以判断通过、失败或未能确认 |
| 优先级 | 先业务使用与明确硬约束，再品牌表达，再装饰细节；冲突需用户决策 |
| 状态 / 待确认问题 | 建议、待确认、已确认、需重新确认；不能自动提升为已确认 |

可观察条件分两类：图中能核验的相对位置、朝向、遮挡；图中无法核验的真实净距、结构受力、消防及隐私性能。后一类必须留待专业设计验证。

## 三个案例的不同答案

九州使用仓库历史人工确认方向；以下两个案例是为本实验明确编写的合成 brief，不代表真实客户项目或真实模型输出。

| 维度 | 九州美学（历史） | 社区烘焙店（合成） | 户外装备体验店（合成） |
|---|---|---|---|
| 项目目标 | 艺术体验与专业服务并存 | 清楚选购、付款、取餐，排队不挡入口 | 浏览装备、独立试背、咨询比较，试用不挡浏览 |
| 使用关系 | 到达→接待↔候客→边缘面询→私密入口 | 入口→面包展示→付款→独立取餐；等候避开入口 | 入口→分类展示→试背区↔咨询台；工作人员可绕行 |
| 品牌表达 | 单套局部珠光系统参与透景及空间衔接 | 烘焙暖色与真实木质展示架；无需艺术装置 | 深绿局部展示背板与耐磨材料；无需珠光层片 |
| 可观察要求 | 座位隔台相向、服务面无遮挡 | 付款和取餐可区分，队列不横切入口 | 装备试用与浏览通道相互分开，咨询可面对面 |
| 不可迁移内容 | 珠光、弱紫、医美节点、五节点数量 | 不复制九州的接待候客系统 | 不复制医美隐私门槛或餐饮取餐流程 |

## 来源与失败经验

- [P7 空间关系](../p7-spatial-layout-contract/P7-layout-contract.md)：把物件清单提升为使用网络；同时说明这是语义契约而非布局引擎。
- [P7a 压缩与保真](../p7a-prompt-budget/P7a-review.md)：去除重复不能损失关系；仍保留长度警告。
- [P7a 残留歧义](../p7a-prompt-budget/P7a-semantic-fidelity.md)：通用的“No artistic installation”表达可能与艺术要求竞争。
- [P7b 图像复核](../p7b-single-generation/P7b-visual-review.md)：开阔度改善，但隔台相向仍失败，双侧巨大艺术围框越界。单张结果不能证明稳定性或确定因果。
- [已有建议预填](../analysis-direction-autofill/README.md)：仅映射当前项目证据、缺项留空、保留人工确认，可作为后续接入点。

## 验证与接入条件

本轮测试直接调用现有独立工作流的建议投影和空间编译器，检查两个合成案例关系传达、无跨案例串味、缺证不补造、输入不被修改，以及九州历史 Prompt 内容摘要保持一致。它只能证明当前机制能承载方法论中的明确表达；不能证明 AI 能从原始文档自行推导这些决策，更不能证明生图质量提高。

下一阶段须使用用户选择的两个真实项目素材，先审核分析来源和决策卡，再在隔离 userData 中做有预算的真实分析/生图对照。相同素材、场景、模型与参数下分别记录基线与候选，预先约定样本数，不择优掩盖失败。记录模型调用数、耗时、终态、报告与图片路径、合成结果。由用户对核心关系、品牌差异、完整性、退化项作人工评价。

进入生产前必须满足：无跨项目内容泄漏；硬关系全部逐项评审；已有九州输入与请求保持可复现；新项目质量达到用户预期；所有相关回归、Golden、repo:verify 与 current-flows 通过。真实验证未完成时不得宣称通用质量通过，不自动接入、合并、发布或刷新验收记录。
