# Confidence Provenance Repair

## Problem

A confidence number generated by the narrative model is model certainty, not source provenance. The canonical Planning claim contract permits confidence only when an upstream source supplies it. The Planning document in this phase has no such parsed confidence authority.

This matters because the frozen hybrid merge contract uses confidence when same-source normalized content collides. A model-invented `0.99` could therefore influence a production merge decision even though no source supports that score.

## Repair

R1.2.1 removes model confidence from every Planning raw boundary:

- removed from `PlanningSemanticExtractionClaim`;
- removed from the prompt JSON shape;
- prompt explicitly forbids confidence and certainty scores;
- removed from the validator allowlist;
- an attempted field is rejected with `PLANNING_MODEL_CONFIDENCE_NOT_ALLOWED`;
- removed from normalization identity/output;
- never emitted by narrative projection.

Consequently, a narrative projected claim has no own `confidence` property and reads as `undefined`.

## Hybrid merge

The R1.1 hybrid merge implementation and policy are unchanged. Structured claims may retain legitimate upstream confidence. Narrative-only semantic content remains eligible for preservation, while same-content narrative claims cannot defeat structured claims using invented confidence.
