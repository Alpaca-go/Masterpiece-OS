## 一、任务目标

当前九州美学最新的零参考图空间生图结果，在整体气质方面已经接近此前人工验收作品，具体包括：

- 暖白、乳白、浅中性色背景；
- 品牌紫色仅作为局部虹彩及识别点缀；
- 轻薄、半透明、珠光、层叠的材料语言；
- 柔和自然光与克制的间接照明；
- 艺术装置与建筑空间相融合的方向；
- 安静、明亮、克制的当代美术馆气质。

**本轮不得重新设计这些已通过的方向。** 任务目标是将当前画面从“装饰精致的高端美容院／医美门厅”进一步提升为“具有当代美术馆尺度、空间组织与叙事的高端医美主空间”。

本轮只解决三项建筑语言问题：**层高感不足、前台旁狭窄走廊造成压迫感、除前台外其他空间属性不清晰。**

## 二、允许与禁止修改的范围

### 允许审计和定向修正

1. 九州美学**项目级确认设计方向**中关于空间尺度、建筑语言、空间组织、艺术焦点及构图关系的描述；
2. 独立【视觉分析与生图】链路中与空间比例、单场景范围、前中后景、运营功能可读性有关的编译与表达，但只有在确认存在通用代码缺陷时才能修改；
3. 项目接待主空间与过渡空间的功能关系、空间递进和负面约束；
4. 所属离线测试、语义追踪、审查报告与预检证据。

### 必须保持不变

1. 已通过的气质、色彩、材料、光影和艺术表达方向；
2. 正常网页生图的 `standard` 路线及**零参考图**机制；
3. 既有四图参考功能：允许保留，不得在本轮启用或设为默认；
4. 其他三个测试项目的既有输出行为；
5. 独立【创意策划】、【视觉迁移】的代码、Prompt、配置与项目数据；
6. 原九州美学正式项目数据、历史图片、已审核基准、Golden 与人工视觉质量状态。

**修改优先级：** 优先改项目级确认设计方向；如果项目级方案即可满足目标，不修改通用空间编译器。确需修改通用代码时，必须提供明确根因及跨行业回归证据，禁止将九州美学特有的建筑风格硬编码为默认规则。

新增自有代码文件、变量、函数、类、配置标识及业务字段**不得采用版本号、阶段号或迭代后缀命名**。不得为去除数字擅自破坏既有依赖、模型标识及历史兼容字段。

## 三、当前问题与修正要求

### 问题一：层高感不足，缺少美术馆尺度

**现象**

- 顶面视觉高度偏低；
- 半透明艺术结构贴近顶面大面积展开，反而强化压顶感；
- 竖向留白不足，立面、门洞与家具共同暗示普通商业室内尺度；
- 虽有柔美的光线和艺术装置，仍呈现美容院／商业门厅感。

**修正要求**

1. 明显提升**视觉净高与竖向空间比例**，让主厅具备更强的展馆尺度感；
2. 通过完整竖向墙面、拔高界面、顶部留白、高侧窗或天光等空间设计方式增强纵向尺度；
3. 半透明装置可参与上部空间组织，但须与建筑净高形成明确关系，不应整体贴顶下压；
4. 保留人体尺度和接待功能真实性，不可仅靠超广角变形、夸张透视或虚构极端层高掩盖问题；
5. 如原始资料未给出实际层高，不得宣称具体米数为已验证设计事实；可用“更高净高感、主厅尺度、竖向留白”等视觉设计目标表达。

**验收依据：** 即使去掉装饰性光效，画面依然应呈现开阔、有竖向呼吸感的展馆式空间，而不是常规商业吊顶空间。

### 问题二：前台旁狭长走廊形成压抑、阈限空间感

**现象**

- 接待台旁直接进入一条细长通道；
- 通道两侧类似连续房门，容易形成机构或酒店内走廊感；
- 视线向远处狭窄尽头收束，空间由主厅突然变得封闭；
- 容易引发压抑、孤立、阈限空间的感受，不符合项目的美术馆定位。

**修正要求**

1. **取消“接待台紧邻狭长走廊、两侧连续开门”的可见空间模式**；
2. 改为“主接待厅 → 开放或半开放过渡空间 → 后续咨询及运营区域”的**空间递进结构**；
3. 过渡区域可表现为次级厅、开阔过厅、半开放候客区、艺术展示与停留空间等，但不应为了满足文字要求而堆砌无功能的大空间；
4. 需要保护的诊疗／咨询隐私仍须成立，可通过转折、退让、非直视的界面、低调入口或边界关系体现；
5. 不以隐藏所有入口、完全取消商业运营通道的方式修复；也不得仅通过改变相机角度把狭窄走廊藏起来。

**验收依据：** 前台之后应是有层次的展开与转场，而不是酒店式双侧开门的细长通道。

### 问题三：空间属性模糊，除前台外缺少功能可读性

**现象**

- 前台能够识别，但候客区域较弱；
- 艺术停留、展陈或过渡关系不够明确；
- 场景更像精美门厅，而非具有完整空间体验的接待主厅。

**修正要求**

1. **接待台**作为到达和服务锚点，保持真实可用；
2. 除接待外，应至少清楚呈现**候客／停留、艺术展示、空间转场**三类关系中的两类；
3. 候客区不能只是画面角落的孤立小沙发，应与主厅尺度、到达流线和艺术焦点共同组织；
4. 艺术装置应构成空间秩序的一部分，参与上部空间、分隔、透景或视觉中心，不应退化为墙面贴饰；
5. 后方可以展示次级空间的视线线索，但不要求把咨询室、治疗室等其他内部空间强行塞入同一镜头；
6. 明确**到达—接待—候客／艺术停留—过渡—隐私边界**的场景层级，避免多项功能在画面上平均争夺注意力。

**验收依据：** 不读 Prompt，仅观察图片，也能理解这是一个带有候客、艺术体验和后续空间层次的接待主厅，而不仅是一张漂亮的前台图。

## 四、建筑语言与构图的综合要求

### 空间构成

- **竖向：** 主厅有明显的展馆尺度、净高感和留白；
- **横向：** 接待台、候客、艺术焦点之间保持舒展距离；
- **纵深：** 使用开敞过渡、半透明界面、局部错位与次级空间形成递进，而非狭长走廊；
- **视线：** 入口视角应可读前景到达流线、中景接待与候客、背景次级空间或建筑留白；
- **动线：** 访客可理解如何接待、候客、继续前往咨询空间，私密功能区仍具合理的非直视边界。

### 既有艺术方向的保护

- 暖白／乳白／浅灰为建筑背景；
- 紫色仅作为少量局部材料内层虹彩或品牌识别辅助；
- 半透明珠光薄片强调清晰的层片深度、自然光透射、柔和反射；
- 艺术性来自建筑、材料、光与空间关系，而非到处布置羽毛符号；
- 避免过度曲线、重复拱券、波浪灯槽、紫色连续发光描边；
- 不能为了“展馆感”创造夸张却无依据的科幻穹顶或不合理结构。

## 五、具体实施顺序

### 第一阶段：离线根因审计

1. 检查最新已人工通过气质方向的**项目确认设计决策**、有效 Packet、正式空间 Prompt、实际 Provider Prompt 和生成图之间的对应关系；
2. 确认“层高不足、狭长走廊、空间属性弱”分别在哪个环节缺少正向空间约束，或是否来自旧分析的隐性提案；
3. 单独评估相机视角、空间功能要求和建筑结构描述，不把镜头技巧当作结构修复；
4. 提交字段来源与修复位置说明，确保本轮修复没有改变已通过的气质字段。

### 第二阶段：项目级定向修正

1. 优先在**独立九州美学测试副本**的设计方向草稿中修订：建筑结构与空间组织、主艺术系统与空间焦点、构图主次、功能网络及跨区域关系；
2. 保留已有色彩、材料及光影字段的结构化内容，除必须修复的局部冲突外不变；
3. 按正式网页确认流程保存、复核并确认修订，不直接写入原项目数据；
4. 如项目级修改已经能生成明确、无冲突的正式 Prompt，不再修改生产编译器；
5. 只有识别出可复现的通用编译缺陷，才允许提出限定代码改动，并附独立测试与其他行业反例。

### 第三阶段：离线编译与回归

1. 使用独立业务的正式编译与标准生成预演路径，获取**实际 Provider 请求**；
2. 保证 `generationBasis: standard`、`referenceAssetIds: []`、请求无 `image` 字段，参考图数量为零；
3. 验证正式 Prompt 已明确表达视觉净高、开敞转场、非走廊式纵深、候客及艺术停留功能，同时仍保留已通过的暖白、珠光、自然光与克制紫色；
4. 检查来源追踪：新的建筑语言来自用户授权的九州美学项目设计方向，不伪装成原品牌素材事实；
5. 比较另三个测试项目的实际标准请求，确认没有无关变化；
6. 保留既有四图参考路线功能，检查【创意策划】与【视觉迁移】隔离；
7. 运行完整性检查、相关包测试、根测试、Golden、Web 与 Runtime 相关验证；任何失败都要如实归因，不得直接刷新 Golden 或绕过守卫。

### 第四阶段：真实生图预检（不执行调用）

1. 仅为独立九州美学测试副本准备预检；
2. 保持上一轮可比的模型、2K、16:9、接待与入口场景、单张输出设置；
3. 确认零参考图、无自动重生成、无自动定向纠正；
4. 记录最终 Prompt、请求摘要、用户确认记录、模型参数与费用风险；
5. **预检完成后停止，等待用户明确授权付费生图。**
