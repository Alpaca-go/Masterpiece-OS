# 种子项目采集清单

用于把一个新项目变成案例库的第五条、第六条记录。目标是**降低录入成本**，不是收集越多越好。

## 需要提供什么

| 项 | 要求 | 为什么 |
|---|---|---|
| 项目素材 | 3–10 张品牌/产品/现场照片；**不要放已通过的空间效果图** | 有成品图会诱导复制，无法验证知识迁移 |
| 基本约束 | 面积、层高、街面/商场、堂食/外带比例、预算档 | 这些决定“成立前提”，是知识库最缺的字段 |
| 验收结果 | 哪张图被接受、哪张被否、为什么 | 知识来自验收与拒绝，不来自模型提案 |
| 项目类型 | 社区/商场/街边、IP/非 IP、快餐/正餐 | 用于判断规则的作用域 |

## 不需要提供什么

- 不需要整理成 PPT；
- 不需要先写设计说明；
- 不需要提供客户隐私或报价；
- 不需要提供已经通过的效果图（除非你想把它作为“人工通过图”单独存证，而不是分析输入）。

## 流程

1. 我把素材导入独立工作流，跑一次真实分析；
2. 你确认方向、出一张或两张图；
3. 你判断“通过/不通过 + 一句原因”；
4. 验收后用 `scripts/extract-case.mjs` 生成草稿；
5. 你补 7 行“人工覆盖”，入库。

## 当前缺的项目类型

- 小面积、外带为主（10–30 平方米）
- 商场里的非 IP 品牌
- 早餐/快餐时段性强的店
- 咖啡/烘焙（需要真实照片，纯文字板会被分析链路拒绝）

任意一个都可以；不需要和冯烫烫“同风格”，相反，**不同约束更有价值**。
