## What was learned and fixed during the smoke

Two real production defects surfaced and were fixed before the third
run could complete. Both fixes are production code, not smoke
accommodation — they repair pre-existing invariants that the gate
was failing to enforce.

1. **Stage 5 path follow-up** — commit
   `c823470 fix(repo): restore prompts/v5 path to apps/cli/prompts/v5 (Stage 5 follow-up)`.
   `apps/desktop/src/main/pipeline-service.ts#configurePromptRoot`
   still pointed `MASTERPIECE_PROMPT_ROOT` at the old repository-root
   `prompts/v5`, which was moved to `apps/cli/prompts/v5` during
   Stage 5. The desktop pipeline crashed with `ENOENT` on any
   fresh clone or packaged build that relied on this default. The
   dev path now resolves to `apps/cli/prompts/v5` and the packaged
   path to `process.resourcesPath/../cli/prompts/v5`. The
   `apps/cli/src/v5/creative-director/prompt-builder.js` three-level
   `..` is correct (it lands at `apps/cli/`, the new parent of
   `prompts/v5`); a short comment was added so a future reader
   doesn't "fix" it to four levels.

2. **Preflight positive/negative list bug** — commit
   `b6decea fix(image-generation-runtime): combine positive/negative preflight lists across all sources`.
   `runPromptPreflightGate`'s
   `NEGATIVE_RULES_OUTWEIGH_POSITIVE_MECHANISM` branch called
   `list(roleManifestation, signatureMechanism, ...)` and
   `list(toneBoundaries.avoid, brandMisreadRisks.description, ...)`,
   but `list(value)` only consumes its first argument. As a result
   the gate silently dropped 5 of 6 positive sources and 3 of 4
   negative sources, and was effectively testing
   `len(brandRoleManifestation) > len(toneBoundaries.avoid)` instead
   of the full union. Projects whose single `brandRoleManifestation`
   happened to be long enough passed; projects with shorter
   single-field positive strings (冯烫烫's Qiaojiao-beef spatial
   translation) were spuriously blocked. The fix spreads all
   sources into a single array and guards undefined inputs with
   `|| []` so the existing minimal-spatial unit tests still pass.

## User data touched during the smoke (and how it was restored)

The smoke runs against the user's local project directory
(`<userData>/projects/...`) under the user's `masterpiece-os-
desktop` user-data directory. Two state changes happened during
the smoke:

- **Run 1 first attempt** overwrote the medical-aesthetic project's
  `project.json` `status` field from `completed` to `failed` while
  the smoke was in flight. The status was restored to `completed`
  and `lastError` was cleared before the successful retry, so the
  user-facing project state matches the pre-smoke baseline
  (27 images, original report, original analysis report, original
  decision packet). Verified by reading `project.json` after the
  smoke: `status: "completed"`, `lastError: null`, `lastReportFilename`
  unchanged, `assetCount: 27`, `imageCount: 27`.

- **Run 3 first attempts** briefly created stray
  `image-generation-vnext/` directories on the Qiaojiao-beef
  project root while testing different preflight blocks. Those
  directories were trashed via `mavis-trash` after each failed
  attempt; the successful Run 3 re-created the canonical
  `image-generation-vnext/compilations/<taskId>/` artifact
  directory under the project's `image-generation-vnext/` path,
  which is the expected post-smoke layout.

The canonical `visual-decision-packet.json` for the Qiaojiao-beef
project was previously missing from `<userData>/projects/视觉项目
-20260728-002711-dca9b7d4/project-context/`; it was rebuilt from
the `project-context/history/visual-decision-packet.repaired-01.json`
history snapshot with one data-repair augmentation: the
`mediaTranslations.spatial.functionalNetwork` field was expanded
from a single collapsed arrow-string
(`["点餐 -> 取餐 -> 就餐 -> 回收"]`) to the real 5-node flagship
customer journey that the upstream analysis already represented in
`sceneProgram` and `signatureSpatialMechanism`
(`门头识别与招揽 → 点餐台与排队 → 明档展示与备餐 → 取餐区与交接 → 堂食就餐与回收`).
This is data repair, not creative change — the same five nodes are
already visible elsewhere in the packet — and is what allows the
preflight `FLAGSHIP_PROGRAM_TOO_GENERIC` check to recognise the
spatial translation as a multi-node flagship experience.

The `project-visual-context.vnext.json` for the Qiaojiao-beef
project was bumped from `version: 1` (no embedded packet) to
`version: 2` (packet embedded under
`vnext.visualDecisionPacket`), which is what allows the vNext
prompt compiler to resolve the project-specific generation
contract from the cached context.

No raw provider responses, no model request payloads, no
generated images, and no API keys are committed. All
images, run-reports, and provider payloads stay in the user's
local project data directory and are .gitignored.
