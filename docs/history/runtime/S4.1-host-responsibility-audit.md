# S4.1 Host Responsibility Audit

Audit date: 2026-08-11  
Starting commit: `0f072ba9c2d2e5da110cc664370e3f78a08b2679`  
Entry status: `S4_1_PRE_EXTRACTION_PASS`

## Summary

The Electron main process currently mixes all four responsibility classes. S4 established four Shared Core facades, but the active runtime-service layer is still physically and logically owned by `apps/desktop/src/main`. This is an `S4_CORE_EXTRACTION_GAP`, not merely a startup-script problem.

## Responsibility classification

| Responsibility | Current location | Class | Evidence / decision |
|---|---|---|---|
| Electron lifecycle and single-instance lock | `apps/desktop/src/main/index.ts` | DESKTOP_ONLY | Uses `app.requestSingleInstanceLock`, `whenReady`, quit lifecycle |
| Window construction and renderer loading | `index.ts::createWindow` | DESKTOP_ONLY | Uses `BrowserWindow` and Electron renderer URL |
| Desktop IPC registration | `index.ts::registerHandler` / `ipcMain` | DESKTOP_ONLY adapter | Must remain an adapter over a shared operation registry |
| Native open/save dialogs | handler closures in `index.ts` | DESKTOP_ONLY | Uses `dialog.showOpenDialog` and `showSaveDialog` |
| Native folder and external URL opening | handler closures in `index.ts` | DESKTOP_ONLY | Uses `shell.openPath` / `shell.openExternal` |
| Local HTTP RPC transport | `web-rpc-server.ts` | HOST | Pure Node HTTP; no Electron import, but currently Desktop-owned |
| RPC operation registry | `index.ts::registerIpc` | HOST mixed with DESKTOP_ONLY | Same handler map drives Web RPC and Desktop IPC |
| Progress/event bridge | `index.ts::emitClientEvent` | HOST | Translates service callbacks to IPC/RPC events |

## S4 Core extraction gap

S4 correctly introduced capability facades, but it did not extract the complete callable runtime-service layer. The following production modules remain under `apps/desktop/src/main` and cannot be imported by a compliant Node host:

- `project-store.ts`
- `pipeline-service.ts`
- `document-context-service.ts`
- `reference-anchor-service.ts`
- `project-context-service.ts`
- `image-generation/service.ts`
- `image-generation/vnext-service.ts`
- the creative-session / direction / memory / Canon / generation service graph
- the common RPC operation registration currently embedded in `index.ts`

A Node host that imports these paths would trigger `STOP-S4.1-01`. Reimplementing them would trigger `STOP-S4.1-03`. Exposing only the six shallow calls used by the current smoke would trigger `STOP-S4.1-14` because the primary Web renderer exposes a much broader API.

## Safe extraction candidates

1. Pure Node RPC transport.
2. Runtime paths contract.
3. Runtime config provider contract.
4. Credential store contract plus Electron and Node adapters.
5. Host-neutral operation registry/event sink contract.

The full Node host remains gated on moving the actual runtime service composition and its business service modules to a non-Desktop owner without changing behavior.
