## 3. 设计动作（带来源）

1. **明档前置 + 木构包烟罩**（分析 + 人工强化）：开放厨房在视觉中心，铜锅、蒸笼、蒸汽、厨师可见；排烟罩收进木构棚架。
2. **暖黄低照度 + 局部灯池**（人工覆盖）：以桌面和明档为重点，保留暗部；不做均匀冷白。
3. **红砖 + 旧木 + 赤陶 + 铜器**（人工覆盖）：白色只作局部抹灰；浅色木只用于桌面/座椅。
4. **经营密度**（人工补充）：桌椅紧凑、真实用餐人群、桌面菜品餐具；宁可略挤，不要空旷。
5. **品牌红克制**（分析与人工一致）：只做菜单板、坐垫、小标识；不做大面积红黑金属。
6. **文字后期合成或图内出字**（人工决策）：v8 使用 `in_image`，品牌文字直接入画；其他项目默认 `post_composite`。

## 4. 成立前提（推断）

- 街面可见、可开门，能做临街门头与明档窗口。
- 层高允许木构棚架与吊灯，不做沉重吊顶。
- 排烟与消防允许开放明档；否则需要玻璃隔断或局部封闭。
- 预算支持砖、木、铜，不追求昂贵石材。
- 经营时段覆盖晚餐，暖光氛围才有意义。

## 5. 禁用 / 误用（对应失败版本）

- **不要白墙 + 均匀亮光**：v1 的实际失败，会变成商场快餐。
- **不要红黑金属大烟罩当主视觉**：烟罩是设备，不是品牌装置。
- **不要玻璃隔断把明档封起来**：v2 的问题，失去“现做”的信任感。
- **不要压暗成酒吧**：v2 过头；暖黄不等于昏暗，仍要可读。
- **不要在图中生成乱码文字**：v5/v7 的教训；`in_image` 只保证“可以出字”，不保证“字一定对”。
- **不要直接复制人工通过图的构图**：通过图是验收标准，不是构图模板。

## 7. 可复用 / 不可复用

**可能复用（需在其他项目验证）：**

- 明档前置 + 木构包住排烟罩；
- 暖黄低照度 + 局部灯池；
- 红砖 + 旧木 + 赤陶 + 铜器；
- 宁可略挤、不要空旷；
- 品牌红只做点缀。

**不能直接复用：**

- 具体构图与镜头（v3 街景 / v8 室内只是本次选择）；
- 红砖比例、木色深浅、吊灯样式；
- 乐山/跷脚牛肉的地域符号；换品类要重新判断。

## 9. 从本卡产生的候选假设（单案例，待验证）

- **H1**：社区烟火气小馆，暖黄低照度优于明亮均匀；模型默认偏亮（本卡分析明确禁止“昏暗”），需要人工覆盖。
- **H2**：明档排烟罩应收进木构/造型，不能成为独立红黑金属体。
- **H3**：菜单板、价签、食材筐等生活细节提升烟火气；但价格必须真实，模型会编。

这三条只是冯烫烫单案例的观察，不能升级为跨案例规则，除非在另一个项目上做“注入 vs 不注入”的对照。

**进展（2026-10-28）**：

- 已在潮牛帮（B）做过一次正对照：H1、H2 在本例成立，但实验组出现过传统风险（厝角头更像庙宇），需要加“现代材料压住传统感”的边界。
- 已在蛙耶（A，商场 IP 品牌）做过一次反例测试：预期“变差”没有发生，模型把经验翻译成原则（暖木、密度、烟罩收进结构），没有复制红砖铜锅；但出现了两个新风险——旗舰感被稀释、模型自行发明品牌道具（摩托车）。两张图自动校验都因“霓虹灯 + 未出现锁定标语”失败，属于测试设置问题。

两轮结果与局限记录在 [candidate-rules.md](candidate-rules.md) 的“H1/H2 对照结果”和“反例测试：蛙耶”两节；强度仍只是单项目单图，不能升级为规则。
