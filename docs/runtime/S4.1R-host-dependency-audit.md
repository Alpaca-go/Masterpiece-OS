# S4.1R Host Dependency Audit

Audit base: `162d9a5`  
Entry branch: `codex/stabilization-s4-1r-node-web-host`  
Recovery tag: `s4-1r-entry-20260811`

## Result

No current business logic remains owned by the Electron host. `S4_2_EXTRACTION_GAP` was not detected. The remaining work is host adaptation only.

| Category | Current Electron owner | Runtime need | S4.1R decision |
|---|---|---|---|
| CONFIG | `settings-store.ts` and `app.getPath('userData')/settings.json` | Public settings, model/profile selection and feature flags | Add a Node config adapter preserving the current settings schema |
| CREDENTIAL | `settings-store.ts` and Electron `safeStorage` | `readCredentials(profileId)` injection | Add a Node secret adapter; never expose keys to Renderer |
| PATHS | `app.getPath('userData')`, analysis prompt-root adapter, configured `defaultDataPath` | User data, projects, outputs and prompt root | Add explicit Node runtime paths; preserve configured project data location |
| RPC | `web-rpc-server.ts` bound by Electron `index.ts` | HTTP health/RPC and SSE events | Reuse the protocol from a Node-owned server and dispatch to the same registry |
| FILESYSTEM | Eleven native dialog/shell channels in `index.ts` | Native chooser/save/open behavior only | Keep Desktop implementations; Node host exposes explicit host-adapter behavior without business logic |
| EVENTS | `emitClientEvent` sends to BrowserWindow and RPC SSE | Analysis/document/reference/image progress | Bind Shared Runtime event callbacks directly to Node RPC SSE |
| PROCESS_LIFECYCLE | Electron single-instance lock, `app.whenReady`, window/quit events | Start, readiness, signals and shutdown | Replace only for Web with Node startup and SIGINT/SIGTERM cleanup |
| DESKTOP_ONLY | BrowserWindow, IPC, dialog, shell, safeStorage, preload | None for Web Primary Runtime | Keep for legacy Desktop; Node host must not import them |
| UNKNOWN | None | — | — |

## Current Web dependency chain

```text
run-web-dev.mjs
  -> electron-vite dev
  -> Electron main index.ts
  -> BrowserWindow + local RPC
  -> Shared Registry + Shared Runtime
```

## Node replacement inputs

`createRuntimeServices(...)` already accepts the real host boundary: settings, credentials, data path, prompt-root adapter, event sinks, save-path adapter and open-path adapter. The Node host will supply these dependencies without altering business services.

## Data compatibility

The Node adapter will accept an explicit `MASTERPIECE_USER_DATA_DIR`. Its platform default will resolve to the same application user-data convention where possible, and `settings.json.defaultDataPath` remains authoritative. No project, report, session or generated-output format migration is authorized.

The frozen-baseline drift checker reports the already approved S4/S4.2 Desktop compatibility moves relative to `deb1cba8`; the S4.1R entry working tree itself was clean. No Prompt file changed and no new behavior-sensitive drift was introduced by this audit.
