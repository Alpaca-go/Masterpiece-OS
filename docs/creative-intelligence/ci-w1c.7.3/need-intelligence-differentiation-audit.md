## GENERIC_NEED_COLLAPSE verdict

**The spec says**: "Flag GENERIC_NEED_COLLAPSE only if distinct Truth becomes same Need set."

Is the Truth distinct? YES — Truth has 2 distinct brand.role values, 2 distinct business.industry VISUAL_SOURCE values, 4-5 distinct locked.assets UUIDs.

Does the Need set capture this distinction? **NO.** All 5 need statements are LITERALLY identical. All 5 need types are the same. Only the UUIDs differ, and the UUIDs don't carry semantic content.

**This is GENERIC_NEED_COLLAPSE.** Distinct Truth (rich brand.role, specific industry inference) collapses into a generic 5-need skeleton (5 types, identical statements, UUID-only reference differentiation).

## How does this collapse happen?

Looking at the need generation logic (inferred from `generatedBy: "deterministic_rule"`):
1. For each UNKNOWN key (business.model, product.core_products) → emit `clarification` need
2. For each LOCKED field (locked.assets, locked.facts, locked.logo) → emit `preservation` need
3. For each identity-conflict (brand.name/role with multiple carriers) → emit `identity` need
4. For each open conflict (source_authority_mismatch, identity_mismatch) → emit `risk` need
5. For each category-defining field (brand.role + business.industry) → emit `differentiation` need

**The collapse mechanism is structural**: the needs are generated from the SHAPE of the Truth (which keys exist, which are unknown, which are locked), not from the VALUES of the Truth. Two projects with the same Truth shape (same keys, same unknowns, same locks) will produce the same needs.

## Impact on downstream

The 5 generic needs are passed to the synthesis prompt as `NEED SKELETON`. The prompt reads:
- "Audience/business-model/brand identity must be confirmed before downstream creative direction can be considered firm."
- "Preserve current brand identity and prevent reinterpretation as another category or brand."
- "Locked assets and locked facts must remain unchanged across downstream creative interpretation."

These statements prime the model to:
- Treat business.model as UNKNOWN (clarification need)
- Preserve current brand identity (identity need)
- Treat locked assets as IMMUTABLE (preservation need)
- Flag the open conflicts as risk (risk need)
- Aim for category differentiation (differentiation need)

The TENSION framework the model then generates IS DOMINATED by these 5 generic needs. The brand.role content (rich value) is referenced in factRefs but is NOT the primary driver of the TENSION axis.

The spec says: "Audit Need genericization. Flag GENERIC_NEED_COLLAPSE only if distinct Truth becomes same Need set."

**Answer: YES, this is GENERIC_NEED_COLLAPSE.**

## Counterfactual: would adding "valuable project facts" to Need help?

If the Need layer included a "valuableProjectFacts" sub-section per need (e.g., "For this project, brand.role is 高端医疗美容服务提供者 which implies 医美 specific constraints..."), the model would have project-specific content in the need.

But this would be a **MAJOR change to the Need schema** (out of scope per spec — see "Don't assume schema expansion is needed"). The audit confirms the current Need is GENERIC, but the fix is not "expand the schema"; the fix is to **let the Truth layer's positive content reach the prompt more directly** (i.e., the prompt's TENSION framework should read brand.role VALUE, not just need IDs).

## Causal chain summary

```
Truth has rich brand.role (project-specific)
        ↓
Need layer strips VALUE and only carries TYPE (5 generic types)
        ↓
Synthesis prompt sees 5 generic need statements
        ↓
Model's TENSION framework is dominated by "lock vs unknown" (project-agnostic)
        ↓
Synthesis output is generic across G01 vs G02
```

**Need layer IS a contributor to first-loss**, but not the ONLY contributor. The model's TENSION framework defaults to "lock vs unknown" because:
1. The Need statements explicitly call out "must be confirmed" and "must remain unchanged" (5 generic statements)
2. The Truth's brand.role VALUE is referenced in factRefs but not directly quoted
3. The Prompt's NEED SKELETON section puts needs BEFORE facts in the user's reading order

The combination of these 3 factors produces the first-loss. The strongest single label is **`NEED_DERIVATION_GENERICIZATION`** (the need layer collapses distinct Truth into generic needs). But the prompt's salience filter is also a contributor.
