# S4.1 Target Runtime Map

## Required target

```text
Web renderer
  -> Local RPC
  -> Node Runtime Host
  -> Shared Runtime operation registry
  -> Shared Runtime service graph
  -> Shared Core
```

```text
Desktop renderer
  -> Electron IPC adapter
  -> the same Shared Runtime operation registry
  -> the same Shared Runtime service graph
```

## Current audited graph

```text
Web renderer
  -> Local RPC
  -> Electron main process
  -> handler registry embedded in apps/desktop/src/main/index.ts
  -> 28 service-named files under apps/desktop/src/main
  -> Shared Core facades
```

## Gap to target

The RPC transport itself is pure Node, but the operation registry and the complete service graph are not shared-runtime assets. `index.ts` registers at least 123 handlers, while image-generation registration adds a separate handler set. The current Web smoke directly exercises only a narrow subset; implementing only that subset in Node would not constitute the Primary Web Runtime.

To reach the target without violating S4.1 stop rules, a preceding remediation must move ownership of the full runtime service layer—without rewriting it—from `apps/desktop/src/main` to a shared runtime package. Desktop compatibility re-exports/adapters may then call that package.

## Safe sequencing required

1. Remediate `S4_CORE_EXTRACTION_GAP` for project, analysis, generation and creative runtime services.
2. Extract the common operation registry and event sink.
3. Introduce runtime paths/config/credential interfaces and host adapters.
4. Instantiate the same runtime service from Desktop and Node hosts.
5. Move Vite/Web startup and authoritative smoke to the Node host.

This sequence is intentionally not executed inside S4.1 because step 1 is a large Shared Core/runtime refactor prohibited by `STOP-S4.1-13`.
