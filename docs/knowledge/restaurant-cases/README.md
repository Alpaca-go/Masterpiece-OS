# 餐厅案例库（第一版，candidate）

状态：**候选知识，未经跨项目验证。** 不是生产规则，不自动进入分析或生图。

## 这是什么

这是餐厅设计知识库的第一层：**案例卡**。每张卡记录一个真实项目的“决策 + 理由 + 成立前提 + 禁用边界 + 证据”，而不是只记风格标签。

目的：当一个新餐厅项目和某个旧项目“气质相近”时，能查到当时**为什么这样做**、在什么条件下成立、什么情况下不能照搬，而不是直接复制元素。

## 两层结构

| 层 | 内容 | 使用方式 |
|---|---|---|
| 行业不变量 | 餐饮经营硬约束（明档可见、动线、外带分离、翻台、排烟等） | 可以作为规则使用，但仍需项目核实 |
| 项目先例 | 单个项目的设计决策与取舍 | 只能作为**建议**，必须人工确认后才进入设计方向 |

本目录目前只有“项目先例”。行业不变量待单独整理并标注来源。

## 卡片字段

每张案例卡固定包含：

1. 基本信息（品牌 / 品类 / 地域 / 项目类型）
2. 九维画像：菜系与产品、经营业态、区位场景、消费客群、服务模式、品牌定位、情绪氛围、地域文化、空间与设计语言
3. 设计动作：具体做了什么
4. 成立前提：为什么成立、依赖什么条件（推断必须标注）
5. 禁用/误用：什么条件下不能照搬
6. 证据：用了哪些图、支持哪条判断
7. 不确定项：图上无法判断的，明确写“未知”

## 使用与边界

- 第三方案例**仅作内部参照与学习**，不得直接复制为交付方案或生成素材；对外交付必须转化为自己的设计语言。
- 案例卡不是验收记录；验收记录单独存放，且需要用户签字。
- 一条经验至少要在 2–3 个不同项目上被应用和修正，才能从“项目先例”升级为“候选规则”，再经过人工确认才可能进入行业不变量。
- 卡片中所有“推断”都不是事实；项目事实以现场和业主确认为准。
