# 设计决策保真度：代码修改与离线验证方案

状态：待用户授权，尚未修改实现。依据：[根因审计](./design-fidelity-root-cause-audit.md)。本方案修复“意图、对象、范围、优先级如何进入 Prompt”，不为九州美学规定专属色彩配方、装置形状或固定风格。

## 通用设计原则

1. 将品牌身份色与室内面积角色分开；材料的颜色、光学行为、承载对象也分开。保留来自当前项目的比例和范围，证据不足则报未决，不能统一把品牌色扩为大面，也不能统一把一切非中性色压为小饰件。
2. 建筑动作必须保留原句的主语、对象和作用范围。“动线流动”不能自动变成曲墙，“层叠光影”不能自动变成层叠天花。允许项目主动选择复杂建筑；不把所有项目改成简约或全部去曲线。
3. 核心艺术装置可以是空间设计主体，同时不承担诊疗运营节点。业务功能与视觉焦点是两个维度，不能因为“不属于功能”就必然从属于墙面装饰。反过来，没有装置意图的项目也不要求新增装置。
4. 项目已确认意图优先；有证据的项目设计提案次之；可选建筑先验仅作支持。行业事实约束用途、隐私和运营，不替代审美定位。没有证据时不承诺具体诊疗动线、物理尺寸或材料参数。
5. 一个决策只在一个主块完整表述；其他块引用该关系，不以关键词重复来制造优先级。冲突须显式报告，不能将互相矛盾的正负要求一起交给 Provider 再期待模型自行决断。

## 分析充分性与用户输入：另列审查项

现有资料能支持品牌紫色和抽象光泽潜力，但不足以断言已确认珠光薄片材质、暖白配比、装置尺度和位置。纯编译修复不会自动制造这些信息。

建议后续在 `src/runtime/unified-visual-understanding.js` 的已有结构中明确区分平面身份色、空间背景角色、材料光学潜力与实施提案；在 `src/analysis-decisions/deliverable-sufficiency.js` 检查“已声称的设计目标”是否有对象/行为/层级支撑，而不是每个项目必须填写同一套艺术内容。`src/runtime/visual-decision-packet.js` 继续使用现有角色/比例/behavior 容器，禁止静默引入必填新协议或用样图观察自动补全。

这部分涉及分析行为与提示词，**本次首批申请不包含修改分析 Prompt 或真实重分析**。需在编译链路证据审查后另作专门评估与授权。已有模型提案保持 proposed/inferred，用户明确定位作为用户输入单独追溯，不能把它回填成原素材中已有事实。原项目不覆盖，输入补充只在用户明确触发的测试副本中进行。

## 离线验收，不使用真实 Provider

| 验证主题 | 可执行断言与反例 |
|---|---|
| 色彩角色可达 | 只改变显式背景/点缀角色或现有 ratio，最终 Prompt 的对应范围必须变化；其余材料和功能不变。品牌主色允许是室内点缀，单色强烈空间也允许来自证据 |
| 双语角色一致 | 同义中文/英文背景角色产生同等空间角色；无证据不能默认为固定主背景 |
| 材料光学完整性 | 有色或中性材料都能保留透射/反射/层厚等已提供描述；颜色限制不得擦除光学行为，不在没有证据时加入珠光/透明性 |
| 对象作用域 | circulation flow 不生成曲墙；层叠灯光不生成天花几何；明确曲线天花仍正确保留；颜色命名不生成建筑几何 |
| 艺术与商业并存 | 有证据的艺术型诊疗空间保留核心装置与接待/隐私关系；功能设施不被艺术物体替代；普通旅馆、餐饮和非艺术诊疗项目不自动长出装置 |
| 场景与先验 | 接待任务不自动混入不匹配的咨询机制；品牌更名不改变项目意图优先级；关闭先验后不影响其余设计角色 |
| 层级与去重 | 核心对象在最终构图约束可定位，背景与功能关系也可定位；同一设计来源不通过三次完整重复加权 |
| 不充分与冲突 | 调色板墙面角色和材料小饰件限制冲突时明确报告；不因字段数量够而宣告设计意图可执行；不知道安装位置不能编造落地/吊装事实 |
| 兼容与隔离 | 旧 Packet/已支持 schema 仍可读取，不改兼容常量；无项目专有规则、无跨业务 import、无历史图隐式输入 |
| 调用策略 | 初图保存、Logo 分阶段校验、无图像编辑能力说明和零自动重生成全部保持通过 |

验证使用新建包内通用离线案例和变形测试，覆盖不同商业类型与强弱艺术意图。九州美学仅作为人工审查的项目证据，不把其运行产物变为确定性测试依赖。用户提到的另外三个真实测试项目，仅在已获对应资料与授权后纳入同等回归；不以虚构案例冒充它们。

获准实施后执行包内相关完整回归、双向隔离反例、`repo:verify`、`repo:check` 与 Golden；固定字节 extraction-parity 可能对有意改变的输出发出失败，必须单列审查，不自动改断言、Golden、共享实现或完整性记录来消除失败。若必须触及包外测试，另报范围，不越界修改。公共宿主 256 != 236 继续独立报告。

## 风险与放行条件

移除强制架构模板可能降低旧模板输出的确定性，也可能暴露现有分析缺口；不以缩短 Prompt 作为质量保证。将所有颜色降为点缀同样会损害其他项目，必须用相反方向的案例验证。艺术意图不等于免除医疗商业功能，功能要求也不等于审美降级。

首批代码即使离线通过，也只证明语义传递与隔离行为。真实视觉质量验证、Provider 调用预算、人工验收、完整性摘要更新均不在本次修改申请内，仍需后续明确授权。当前只申请上述保真编译链路的离线实施；不合并、不发布、不冻结、不改 Golden。
