## Native Desktop exceptions

These channel shapes remain Desktop adapters because they require native UI/shell behavior, while their surrounding business operations move to the registry:

```text
projects:choose-files
projects:choose-folder
report:export
report:open-folder
document-context:choose-documents
document-context:export
document-context:open-folder
reference-anchor:choose-reference-assets
reference-anchor:export
reference-anchor:open-folder
image-generation:open-folder
```

File export operations that combine business path resolution with native dialogs must be split into a shared path/read operation and a Desktop save/open adapter without changing the public channel payload.

## Current dispatch shape

```text
registerHandler(channel, closure)
  -> ipcMain.handle(channel, closure)
  -> webRpcHandlers.set(channel, closure)
```

The same closure already serves IPC and Web RPC, but registry ownership is embedded in Electron `index.ts` and many closures contain business coordination.

## Target dispatch shape

```text
Electron IPC adapter ----┐
                        v
Shared Operation Registry.execute(channel, args)
                        |
                        v
Shared Runtime service graph
```

Future Node RPC will call the same registry in S4.1R.

## Migration batches

1. Registry skeleton and host-neutral contracts.
2. Project/report operations, leaving native chooser/open/save adapters in Desktop.
3. Analysis operations.
4. Document/context/reference operations.
5. Image/Space/Packaging operations.
6. Creative operations.
7. Settings adapter routes and remaining operation reconciliation.

Each batch keeps existing channel strings and argument order. The registry dispatches only; it must not contain business implementations.
