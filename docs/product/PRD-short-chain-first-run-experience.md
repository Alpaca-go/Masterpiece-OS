# PRD: Short-Chain 首次使用体验重构

**Status**: Draft
**Author**: Alex (PM)  **Last Updated**: 2026-08-24  **Version**: 0.1
**Stakeholders**: Eng Lead, Design Lead, QA

---

## 1. Problem Statement（问题陈述）

新用户打开 Masterpiece OS 后，无法快速理解"这是什么、我该做什么、
我能得到什么"。当前 UI 充满内部术语（Short-Chain、Reference Anchor、
Brief、Preflight），对不熟悉产品的用户极不友好。

**具体表现**：
- 空状态没有清晰的行动指引，用户不知道从哪里开始
- 生成过程中没有透明的进度反馈，用户不知道发生了什么、还要等多久
- 失败时展示技术错误信息，用户不知道该怎么办
- 功能命名是工程师视角，不是用户视角

**Evidence（证据）:**

- 用户研究: **待补充**（本项目启动前需完成 5 次用户访谈）
- 行为数据: **未知**（度量体系建立后补充基线）
- 客服信号: N/A（尚无公开用户）
- 竞争信号: Midjourney 通过 Discord 机器人的对话式引导降低了首次使用门槛；
  可画的模板市场让用户"从一张接近的图开始"而不是从零开始

**不解决的代价**：不管技术多强，如果用户在 3 分钟内搞不懂怎么用，他们就会离开，
并且再也不会回来。首次体验是产品的第一道护城河。

## 3. Non-Goals（不做的事）

- **不**改变 Short-Chain 后端业务协议（`imageGeneration.startShortChain` 等 17 个 channel）
- **不**改变生成质量、Prompt 模板、Provider 配置
- **不**做完整的新手引导教程（onboarding tour）——V1 只做即时上下文帮助
- **不**引入新的生成模式或功能（如批量生成、模板库）——这些是后续迭代
- **不**做移动端适配
- **不**重写整个 UI 设计系统（视觉重做是并行项目，但体验重构优先）

## 4. User Personas & Stories（用户画像与故事）

**Primary Persona**: Li — 品牌设计师，28 岁，在一家中型设计 agency 工作。
每天用 Figma 和 PS，对 AI 工具有好奇心但觉得"大多不好用"。
听说 Masterpiece OS 能从品牌文档一键生成一致风格的图，想来试试。

**Secondary Persona**: Wang — 营销主管，35 岁，中小企业市场部负责人。
不是设计师，但经常需要做活动海报、社媒图。试过 Midjourney 但觉得
"调 Prompt 太费时间，而且每次风格不一样"。

---

### Story 1: 作为新用户，我想打开就知道该做什么，以便快速开始

**Acceptance Criteria（验收标准）**:

- [ ] Given 首次打开应用（无历史项目），when 页面加载完成，
      then 我能在 3 秒内说清楚"这个工具是做什么的"
- [ ] Given 空状态页面，when 我看到主 CTA 按钮，
      then 按钮文案是动词开头的行动指令（如"导入品牌文档"），
      而不是内部术语（如"New Project"、"Create Short-Chain"）
- [ ] Given 空状态，when 我不确定该做什么，
      then 页面上有 1 句话解释"上传品牌文档 → 自动提取品牌规范 → 生成符合风格的图片"
- [ ] Given 我有历史项目，when 打开应用，
      then 最近的项目排在最前面，且有清晰的"新建项目"入口

---

### Story 2: 作为用户，我想在生成过程中知道发生了什么，以便决定要不要等

**Acceptance Criteria（验收标准）**:

- [ ] Given 我点击了生成，when 生成正在进行，
      then 页面显示当前所处阶段（分析中 / 编译中 / 生成中 / 即将完成）
- [ ] Given 生成进行中，when 我看进度指示，
      then 有视觉化的进度条或步骤指示器，而不是只有一个转圈的 loading
- [ ] Given 生成超过 30 秒，when 我看页面，
      then 有"预计还需 X 秒"的预估时间（可以是粗略估算）
- [ ] Given 生成进行中，when 我想离开，
      then 有明确的"可以后台运行，完成后通知你"的提示
- [ ] Performance: 生成进度更新延迟 < 2 秒（从后端状态变更到前端展示）

---

### Story 3: 作为用户，生成失败时我想知道为什么以及该怎么办，而不是看到一串报错

**Acceptance Criteria（验收标准）**:

- [ ] Given 生成失败，when 我看错误提示，
      then 提示用用户能理解的语言描述问题（不说 "500 Internal Server Error"、
      不说 "ProviderError: code 429"）
- [ ] Given 生成失败且可重试，when 我看错误页面，
      then 有一个明显的"重试"按钮
- [ ] Given 生成失败是因为内容合规，when 我看提示，
      then 提示告诉我"可能是什么原因触发的"以及"可以怎么调整"
- [ ] Given 生成失败是 Provider 侧问题，when 我看提示，
      then 提示告诉我"不是你的问题，我们正在处理"，并建议稍后再试
- [ ] Given 任何失败，when 我想反馈，
      then 有一个"告诉我们哪里不对"的入口（自动附带运行 ID）

---

### Story 4: 作为用户，我想用我理解的语言来使用功能，而不是学习内部黑话

**Acceptance Criteria（验收标准）**:

- [ ] Given 我浏览整个产品，when 我看到功能名称，
      then 没有 "Short-Chain"、"Reference Anchor"、"Brief"、
      "Preflight" 这类内部术语出现在用户可见的主界面
### 术语替换对照表（UI 层映射，不影响后端）

| 内部术语（代码/API） | 用户可见文案（UI 展示） | 说明 |
|---------------------|----------------------|------|
| `Short-Chain` | **智能生成** | 主功能入口名；简洁直白，强调"AI 帮你生成" |
| `Reference Anchor` | **风格参考图** | 描述作用而不是技术实现 |
| `Brief` | **品牌信息** | 用户更容易理解的说法 |
| `Preflight` | **生成前检查** | 描述行为，不使用航空术语 |
| `Run` / `Generation Run` | **生成任务** | 更贴近日常语言 |
| `Project` | **项目** | 保持不变，这个用户能理解 |
| `Provider` | **AI 模型** | Settings 里用，不说"提供商" |
| `Profile` | **配置方案** | 或"模型配置"，比 Profile 直观 |

**实施原则**：
- 只改前端展示层（`.tsx` 里的文案、按钮文字、标题、Tooltip）
- 后端 API、类型定义、变量名、operation 名称**完全不动**
- 前端 SDK 层（`web-api.ts` / `sdk/`）的接口名也不改，保持与后端一致
- 建议通过一个轻量的文案常量文件统一管理，避免散落在各处
- 确认最终命名前，先在用户测试中验证哪个词最容易理解

## 5. Solution Overview（方案概述）

本次重构聚焦在**首次使用的端到端体验**，而不是整个 UI 的视觉重做。
核心思路是"说人话、给方向、减摩擦"。

### 5.1 空状态 / 首页

当前：展示项目列表 + "New Project" 按钮，没有任何解释。

重构后：
- 首屏有清晰的标题 + 副标题，一句话说清产品价值
- 主 CTA 是"导入品牌文档"（最大、最醒目）
- 次 CTA 是"从空白开始"（更小、灰度）
- 下方有 3 步流程图示：① 上传文档 → ② 自动提取品牌信息 → ③ 生成风格一致的图片
- 有历史项目时，上方是"新建"区，下方是"最近项目"列表

### 5.2 项目创建 / 文档上传

当前：弹出一个表单，让用户填项目名、选文件，术语众多。

重构后：
- 简化为一步：拖放或选择文档
- 项目名自动从文档标题提取，用户可修改
- 上传过程中显示解析进度（"正在读取文档…"、"正在提取品牌信息…"）
- 解析完成后，展示提取到的品牌信息摘要，让用户确认或编辑
- 提取失败时，引导用户手动填写关键信息（品牌名、行业、风格描述）

### 5.3 生成主界面

当前：功能很多，标签页复杂，用户不知道从哪开始。

重构后：
- 左侧：品牌信息摘要 + 参考图区（可添加/删除）
- 中间：大图预览区（生成前显示占位 + 场景选择）
- 右侧：生成设置（场景类型、数量、风格强度等）——折叠起来，默认只显示最常用的 2-3 项
- 底部：一个大的"生成"按钮
- 顶部状态栏：当前项目名 + 生成状态

### 5.4 生成中状态

当前：一个小的 loading 图标 + "生成中"文字。

重构后：
- 全屏遮罩 + 中央进度卡片
- 4 步进度指示：① 分析品牌信息 → ② 编译生成指令 → ③ AI 生成中 → ④ 完成
- 当前步骤高亮，已完成步骤打勾
- 超过 30 秒后显示"预计还需约 X 秒"
- 底部提示："可以切换到其他页面，完成后会通知你"
- 有"取消生成"按钮（二次确认）

### 5.5 失败状态

当前：Toast 提示一条技术错误信息。

重构后：
- 生成区域替换为失败状态卡片
- 图标 + 标题（如"生成没能成功"）
- 一行解释原因（用户友好的语言）
- 建议行动（重试 / 调整设置 / 稍后再试 —— 根据错误类型动态显示）
- 底部小字："错误代码: XXXXX" + "反馈问题"链接

---

### 关键设计决策

- **Decision 1**: 我们选择"渐进式披露"而非"一次展示所有功能"，
  因为新用户的认知负荷有限。取舍：高级用户需要多点一步才能看到全部设置，
  但可以通过"展开高级设置"一键展开。

- **Decision 2**: 我们把错误文案按错误类型定制（至少 5 类），
  而不是统一的"生成失败"，因为不同失败原因用户的应对方式完全不同。
  取舍：需要更多文案工作和错误分类的工程支持，但用户体验提升显著。

- **Decision 3**: 我们先不做完整的新手引导（onboarding tour / 气泡引导），
  因为还不知道用户具体在哪里卡住。先通过数据和用户测试找到真正的卡点，
  再有针对性地做引导。取舍：可能短期激活率不如有引导的版本，
  但避免了"为了引导而引导"的过度设计。

**已知风险**:

| 风险 | 可能性 | 影响 | 缓解措施 |
|------|--------|------|----------|
| 术语替换导致老用户困惑 | Medium | Medium | 第一次打开时显示"界面更新了"的提示，简要说明变化 |
| 后端生成阶段粒度不够细 | Medium | High | 先做粗粒度（3 阶段），后续细化；前端有 fallback 方案 |
| 改动范围蔓延到 UI 重做 | High | High | 严格限定范围：只改体验，不重做视觉设计系统；视觉重做走独立项目 |
| 用户测试招募困难 | Medium | Medium | 先用内部用户 + 朋友圈招募；如果不够，再考虑外部渠道 |

## 7. Launch Plan（发布计划）

| Phase（阶段） | 时间 | 受众 | 通过标准 |
|-------|------|------|----------|
| 用户访谈 | Week 1 | 5 名目标用户 | 访谈完成，洞察整理成文档 |
| 原型设计 + 可用性测试 | Week 2 | 5 名测试用户 | ≥ 4/5 用户能独立完成首次生成 |
| 开发 — 空状态 + 项目创建 | Week 3 | 内部 | 流程跑通，埋点完整 |
| 开发 — 生成进度 + 失败状态 | Week 4 | 内部 | 所有错误类型都有对应文案和 UI |
| 内部 Alpha | Week 5 | 团队 + 5 名种子用户 | 无 P0 Bug，核心流程顺畅 |
| 全量发布 | Week 6 | 所有用户 | 核心指标趋势正向，无严重反馈 |

**Rollback Criteria（回滚标准）**: 如果首次生成成功率下降 > 10pp 或
错误率上升 > 5pp，回滚到旧版 UI 并排查原因。
