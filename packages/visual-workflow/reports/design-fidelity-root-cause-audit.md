# 视觉分析到空间生图：设计决策保真度根因审计

日期：2026-10-16。范围：独立视觉分析与生图。状态：只读审计与修改提案；未修改生产实现，未新增真实模型调用，未更新完整性摘要、Golden 或兼容契约。用户已明确本轮最新图片人工不通过，低于最初三张验收作品；本报告据此记录现状，不作质量冻结或主线合并。

## 结论

问题不只是“装置关键词不够多”。当前链路同时存在：空间意图信息不足、语义转换越权、有效设计角色没有进入 Prompt，以及功能/建筑先验压过项目层级。模型实际执行又出现了与约束不一致的可见结果。仅加强“出现某种艺术元素”的频率，不能解决这些问题。

行业识别本身有素材依据：`九州美学视觉方案-10.png`（cff2880c）明确写有 cosmetic medicine。问题是“医美”作为功能事实，随后与普通高端机构的设计建议混合，却没有保留本次用户明确的艺术展馆气质、整体艺术装置与临床运营并存的优先级。该定位在旧 ProjectRecord 没有文字 brief，不能倒推旧模型已接收并违背本次新指令。

最优先的可复现缺陷是：空间色彩角色在中间层存在但未被最终编译使用；建筑动作对普通词汇作了过强实体扩展；艺术装置虽然保留原句，未进入构图焦点；自动品牌名锚点包含场景不匹配项，并用强制措辞约束概念。

## 可复现根因与分类

### A. 分析输入和设计决策不充分（已确认字段缺口；不能伪装为已丢失事实）

**输入证据**：原项目无文字 brief；主要是品牌识别与应用样机。平面主色有依据；方案10的行业文字有依据。三张历史空间图未作为当前标准生图参考输入。本次用户新增“艺术展馆气质”的明确定位。

**输出证据**：Packet `projectFacts.brandRole` 为科学、美学、工艺与信任；空间概念为优雅、神秘、专业。材料仅有透光/渐变/光滑等泛化描述；装置没有位置、尺度、核心/背景关系。报告虽显示 ready，实质只满足字段非空等门槛，未证明足以执行高审美意图。

**判定**：暖白占比、珠光具体行为、核心装置的空间关系在现有 Packet 中不足；不能只修下游来“恢复”从未被准确编码的关系。需要把本次用户定位作为明确的新项目输入，并要求分析区分观察、推导、提案、待确认。不能把历史图的观察直接改写为输入事实或通用生产常量。

### B. 空间转换的实体越权与语义降级（确定性代码证据）

1. **词汇直接变建筑动作**。`semantic/action-verbs.js:7` 把 flow 与 curve 放在同组；输出固定为 curved walls。实际 functionalNetwork 的 directional flow 经转换参与生成“walls bend into continuous curved surfaces”。层叠/光影纹理又可映射到“ceilings layer in overlapping planes”（同文件:23），天花词自动导致“the ceiling carries the primary spatial gesture”（:155）。这是从属性/运营意图到具体建筑实体和优先级的扩写，不是模型自由发挥。证据在 trace 的 semantic.rewrite。
2. **颜色名称也可产生建筑形态**。实际 `colorSystem.primary` 的 Peacock Violet 在语义轨迹被改写为 layered radial Violet，触发 layered ceiling/radial planes。该贡献有轨迹记录；由于其他字段也有层叠词，不能宣称它单独造成当前天花。
3. **艺术被当作从属装饰的规则风险**。`sanitize-brand-expression.js:11,44` 对“空间作为艺术画廊”等表达直接删除。通用离线输入“空间作为艺术画廊，艺术装置与接待功能共同组织动线”实际输出为空、reason=gallery_poetry_non_commercial。本次旧 Packet 没有这句，因此这是与新定位冲突的已复现通用风险，不能冒充这次旧 Packet 的实际删除事件。
4. **材料颜色规则覆盖材料角色**。实际紫色材料的 brandRole 从轻盈/光泽/装饰或隔断变成统一小件点缀限制。另一个无品牌测试输入“蓝色半透明玻璃；半透明层片用于隔断，边缘透光，低镜面反射”会因含隔断而把整句 optical behavior 替换为颜色限制（:106,121）；这个是通用反例，不是声称实际项目已拥有低镜面参数。

### C. 编译丢失与约束竞争（已由真实 Prompt 和反事实输入复现）

1. **色彩角色失效**。`source-adapter.js:165` 建立 layers.color，但 `compiler.js:255` 的顺序和各 renderer 不渲染它。离线只反转 primary/secondary 的显式 spatialUsage，或更换 secondary 名称并设置 ratio=83，最终 Prompt SHA-256 均完全不变。后者比例仅是探针，不是该项目建议。中文背景 role 解析为 secondary_surface，英文 background 解析为 dominant_field，说明角色解析也不一致。
2. **扩展字段不是当前已生效契约**。normalizer `visual-decision-packet.js:33` 只保留颜色 name/role/ratio，额外 spatialUsage/surfaceApplicability 会被移除；当前项目本来没有这两个字段。这是未来方案必须处理的边界，不是本轮原资料真实携带这些字段而被删除的证据。修复不得假设新字段已存在，更不能偷偷升级历史契约。
3. **装置未进入构图焦点**。实际 layers.composition.mustBeVisible 只有 Reception desk and counter、Privacy partitions or curtains。大型装置文本保留在 brand_translation，但输出焦点清单不含它；医疗床、咨询家具等普通功能项被 splitMustBeVisible 分到品牌段。字段间的主次关系没有被编译为统一约束。
4. **功能范围超出当前画面**。`compiler.js:161` 写 must be legible in one image。standard reception 的场景来源仍为 project_wide（`source-adapter.js:315` 后分支），全院五个功能节点在桥和功能段各重复一次。用户要求真实商业功能，不等于把所有诊疗区域塞进接待画面。
5. **架构优先与反画廊固定语句**。`compiler.js:109,117` 固定要求不要变 gallery、品牌附着建筑；`architecture-context.js:133` 要求概念不得与锚点冲突。这不是本次素材推出的项目要求，与用户当前定位竞争。

### D. Architecture Context 的来源、选择与重复（已确认，模型影响强度待评估）

自动来源：`generation/compile.js:118` 以品牌名匹配既有 registry，即使未提供项目自己的 anchor 选择。不是输入图片被识别后临时选出的材料事实，也不是本轮新增规则。

接待任务实际选中两个 0.85 分锚点，另加一个 0.55 分的 ConsultationFacade；后者 sceneTypes 不含 reception，但行业匹配即可通过 OR 条件（`architecture-context.js:92`），默认上限3让它填入。三个先验同时带入膜顶/金属发光柜台、玻璃入口与木柜台、咨询区大跨天窗等不同场景机制。

Prompt 文本总计8733字符，其中五类建筑相关块4970字符（约56.9%，**包含商业桥，并非纯建筑词或注意力权重**），品牌转译742字符（约8.5%），材料324字符。颜色/暖材质句逐行重复3次，全院功能5句各重复2次。当前机构类要求和建筑动作的重复多于核心装置关系；这证明文本冗余与优先级竞争，不能直接等同模型注意力因果。

离线去掉 brandKey 后，仅 architecture_context 块消失，Prompt 变7594字符，其余块逐字相同。这说明只关闭锚点不能消除上游动作模板和功能扩张，不建议把“关锚点”当作全部修复。实际请求没有上传这些锚点图片，本次只分析其文本影响。

### E. 模型执行偏差（可见不一致成立；独立因果未建立）

最终 Prompt 明说有色材料不得用于隔断等主体，最新图却有明显连续紫色隔断；这构成指令与图像的可见不一致。与此同时，材料名、紫色气质句、玻璃、灯带与先验相互竞争，不能据此把全部责任归给模型或证明更强负面词就有效。

大型主题图像成为壁面表现，与旧 Packet 的背景墙融合建议相容；没有足够证据判定模型单方面把一个明确落地、指定尺度的空间装置降级。珠光光学细节本来未充分进入要求，不能把缺少珠光全部列为 Provider 未执行。真正可确认的是用户人工不通过，而非自动校验的 matched/passed 能证明设计保真。
