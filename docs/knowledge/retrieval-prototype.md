# 检索原型（只读）

状态：**原型，命令行，只读。** 不调用模型、不写任何文件、不自动注入到生图请求。

## 解决的问题

知识库里已经有 13 张第三方标杆、2 张自有案例、1 条图集和 2 张气质卡，但只有"记得住"的时候才用得上。这个脚本把"翻卡片"变成一次可复现的查询，并把**为什么**返回这条一起打印出来。

## 用法

```bash
node scripts/knowledge-search.mjs \
  --category "社区粉面" --tier "平价快餐" \
  --constraints "小面积,外带" --direction "老招牌,烟火气"

# 机器可读
node scripts/knowledge-search.mjs --category "点心烘焙" --json
```

输出固定三段：**3 条先例**（含命中词、成立前提、禁用边界）、**1 条反例候选**（为什么像但不一定成立）、**2 条风格参考**（来自参考图集）。

## 口径（重要）

- **匹配是关键词，不是语义。** 这样每一条结果都能被人核对；代价是同义改写会漏检。已内置一组小同义词表（奶茶/饮品/果汁、点心/烘焙/糕点、社区/街边/底商……），仍可能漏。
- **反例是"候选"**，不是结论：脚本只负责挑出"看起来像但可能不适用"的卡，判断仍然是人。
- **只读**：要用结果时，人工把条目抄进 `knowledgeContext`，或选一个气质预设。脚本不写任务、不改 Prompt。
- 自有验收案例单独列出（当前 2 个），因为规则升级只认自有项目。

## 已知限制

- 没有向量检索、没有排序学习；分数只用于排序，不代表相似度。
- 卡片的中文表达差异会直接影响分数（例如"烟火气"与"市井"命中不同）。
- 图集只有 1 条，风格参考这一段目前基本是空的——要有量才谈得上检索。
