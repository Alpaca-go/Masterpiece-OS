## 既有架构先验的影响范围

实际初次和第二次 Prompt 均包含既有 Architecture Context 的三个架构锚点，涉及膜天花、接待台、幕墙和咨询区机制；同时 Architecture Language 明确顶面承担主要空间姿态。这些是原有文本先验，本轮未改，也不是实际上传的参考图（标准生图请求没有 image 字段）。因此不能把本次建筑风格只归因于 Packet，亦不能把“没有图片参考”理解为“没有架构先验”。这些先验与 Packet 的 S 曲线/层叠描述叠加，构成需要后续分离变量研究的输入；现有证据尚不能证明哪一段文字贡献最大。

## 已确认的问题与推断边界

已确认：首轮 validator 将待合成 Logo/字体的缺失归为 locked_asset_violation，触发第二次收费生图；第二次仍无 Logo 却 passed。两次标准请求均未携带首图，所谓纠正实际是全文 Prompt 驱动的另一次生成，不能保持首图构图、材质、对象或细节。二次验证未做与首图的偏好比较，passed 不能成为替换或排序依据。

文本支持的推断：颜色语句的重复与相互冲突、偏向玻璃/金属/光缝的材料描述、建筑曲线机制与装置机制竞争，可能共同影响了紫色扩散、材质偏移和主次混乱。它们不构成已验证的模型因果；不得仅凭这两张非确定性输出宣布 Prompt 调整方向已经有效。

现有通用 compiler 已有色彩降为点缀的约束，但结果仍偏紫，说明“约束出现”不足以证明约束实际奏效。当前证据不足以判断是权重、模型执行、分析证据不足或其组合造成；下一轮应在获授权后以可追溯任务独立评估，而不是继续自动重试。
